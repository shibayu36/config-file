# Markdownで書く

資料は次の形の1つのMarkdownにする。

````markdown
<何のための変更かを1行>

## 地図

| # | 読む単位 | 性質 |
|---|---|---|
| 1 | <単位名> | <機械的な変更 / 挙動を変えない整理 / 機能追加 など> |

<単位どうしの関係のflowchart>

載せなかったファイル: <ファイル名>

## 動作確認したこと

- <機能が動く事を確かめるために、何をどう確かめたか>

## 1. <単位名>

なぜ: <あるときだけ>

見るポイント: <このdiffで何を見ればよいかを1〜2行>

<図。あるときだけ>

<diff、またはbefore/after>

テストが確かめていること:
- <確かめている仕様を短く（テストケース名）>

<テストのdiff、またはbefore/after>

特記:
- <あるときだけ>
````

- diffは`diff`のコードブロックで、before/afterは対象の言語のコードブロックを2つ並べて見せる
- diffやbefore/afterのコードブロックには、1つずつ直前にファイルのパスを書く。before/afterでは、どちらが変更前かも書く
- 図はMermaidで描く。単位どうしの関係と、責務の移動の変更前後の構造はflowchartにし、変更前後はsubgraphで並べる。処理の流れはsequenceDiagramにする
