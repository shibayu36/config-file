# HTMLで書く

資料のデータを`guide.json`に書き、描画スクリプトで1つのHTMLにする。HTMLは、外部（CDN、別ファイルのCSS・JS、ネットワーク）を何も読み込まずに表示できる1ファイルにする。diffの見た目（色分け、inline/splitの切り替え、空白の変更を隠す切り替え、変わった単語の塗り、注釈の見せ方）はスクリプトが揃えるので、`guide.json`には中身だけを書く。

コードの行は`guide.json`に写さず、行番号の範囲で書く。展開スクリプトが範囲の行をgitから写し、`lines`に行が入った形に書き換える。

## 作り方

スクリプトは、このファイルからの相対パス`../scripts/`にある。どれも対象のリポジトリのルートでnodeで実行する。`base`・`head`のcommitからファイルを読むので、そのcommitがリポジトリにある必要がある。

1. `numbered-diff.mjs <base> <head>`で、各行に`b<baseの行番号>`・`h<headの行番号>`を付けたdiffを読む
2. `guide.json`を書く。HTMLと同じ場所に置く。コードを見せるブロックには、`lines`の代わりに`range`を書く（「範囲の書き方」）
3. `expand-guide.mjs <guide.json>`で展開する。`range`を持つブロックが、`lines`に行が入った形に書き換わる。範囲に誤りがあればファイルは書き換わらずにエラーで止まるので、直して走らせ直す
4. `render-html.mjs <guide.json> <出力するHTML>`で描画する。形のエラーで止まったら、`guide.json`を直して作り直す。「実ファイルと合わない行」の警告は、写し間違いなら直す。途中のcommitにしか無い行を意図して見せている時は残してよい。その行は行番号が付かず、その行だけで色分けされる

### 展開した後に直す

`guide.json`を直す時は、該当する箇所だけを書き換え、`guide.json`全体を書き直さない。

- 追いcommitの後は、`head`（変わったなら`base`も）を新しいcommitに変えて描画する。変わった行が「実ファイルと合わない行」の警告に出るので、その行を`guide.json`から探し、前後だけを読んで`lines`を書き換える
- 追いcommitで増えた変更は、新しいブロックを`range`で書いて足し、もう一度展開する。展開は`range`を持つブロックだけを書き換えるので、何度走らせてもよい
- ブロックの範囲を変えたい時は、`lines`を直接書き換えるか、ブロックを`range`で書き直して展開し直す

## guide.jsonの形

```json
{
  "title": "<何のための変更かを1行>",
  "base": "<PRの分岐元のcommit>",
  "head": "<PRのheadのcommit>",
  "map": { "figure": ["<単位どうしの関係の図>"] },
  "omittedFiles": ["<載せなかったファイルのパス>"],
  "checksSource": "<動作確認の出どころ。例: PR 本文の「動作確認」から。>",
  "checks": ["<動作確認したこと>"],
  "units": [
    {
      "title": "<単位名>",
      "nature": "<性質>",
      "why": "<なぜ>",
      "points": "<見るポイント>",
      "figure": ["<図>"],
      "blocks": ["<ブロック>"],
      "tests": {
        "groups": [{ "title": "<テストファイルなど>", "items": ["<確かめている仕様>"] }],
        "blocks": ["<テストのブロック>"]
      },
      "notes": ["<特記>", { "text": "<特記>", "items": ["<入れ子の項目>"] }]
    }
  ]
}
```

- `why`・`figure`・`tests`・`notes`・`omittedFiles`・`checksSource`・`tests.groups[].title`は、無ければ項目ごと省く
- 地図の表は、スクリプトが各単位の`title`と`nature`から作る。`omittedFiles`が空なら「なし」、`checks`が空なら「記載なし」と出す
- ファイルのパスは、リポジトリのルートから書く
- 文章の中で使える書式は`` `コード` ``だけ。箇条書きは配列にし、入れ子は`{ "text", "items" }`にする

### ブロック

| `kind` | 使う時 | 項目 |
|---|---|---|
| `diff` | diffで見せる時 | `file`、`caption`（省略可）、`range` |
| `beforeAfter` | 構造や責務の移動 | `before`と`after`に、それぞれ1つ以上の`{ "file", "caption", "range" }` |
| `code` | 変更の無いコードや、新規ファイルを全部追加の色にせずに見せる時 | `file`、`caption`（省略可）、`range` |
| `text` | ブロックの間に挟む短い文 | `text` |
| `list` | 機械的な変更で、変更した箇所を一覧にする時など | `items`（箇条書きの配列） |

- `diff`で省いた行は、読み手が`"@@"`の行を押すと実際の位置に開く。開けるのは、その`"@@"`から次の`"@@"`（無ければブロックの終わり）までの区間に、省いた変更がある時。区間に実ファイルと合わない行があると開けない。ファイルの中身を丸ごと省く時は、`"@@"`の行だけの`diff`ブロックにする
- 注釈（`[AI注]`を含むコメント）は照合から外れ、背景色で見分けられるように出る
- `beforeAfter`では、変更前と変更後の行を字下げを無視して比べ、片側にしか無い行を削除・追加の色で塗る。片側だけ省くと、もう片側の同じ部分が丸ごと塗られるので、省く部分は両側で揃える

### 範囲の書き方

```json
{
  "kind": "diff",
  "file": "src/routes/reply.ts",
  "range": [
    "@@ export function postReply",
    "h40-h52",
    { "note": "// [AI注] attachments の引数は「5. 添付のコピー・保存・後始末」で読む（省略）" },
    "h60-b75"
  ],
  "lineNotes": { "h70": "// [AI注] main ではレスポンスを返す前に作っていた" }
}
```

`range`には、次の要素を出したい順に並べる。

- `"@@ <文>"`: 区切りの行になる。`"@@"`の後ろに書いた文は、区切りの行にそのまま出る。`diff`だけで使える
- `"<端>-<端>"`: 両端の間の行をすべて出す。1行だけなら`"h40-h40"`のように両端を同じにする
- `{ "note": "<注釈>" }`: 独立した注釈の行になる。字下げはスクリプトが次の行（無ければ前の行）に揃える

`lineNotes`には、行末に注釈を付ける行の端と、注釈を書く。注釈は、`range`に含まれる行にだけ付けられる。注釈の文には、対象の言語のコメント記号と`[AI注]`を含める。

端の書き方は、ブロックの種類で変わる。

- `diff`: `numbered-diff.mjs`の出す`b…`・`h…`で指す。範囲はファイル全体のdiffの並びで数え、両端の間にある`-`・`+`・変更の無い行をすべて含む。`...`をまたぐ範囲は、`...`で省かれた変更の無い行も出す。変更の無い行は`b`と`h`のどちらでも指せる
    - 削除だけを出す: `"b40-b45"`
    - 削除で終わる: `"h30-b48"`
    - 削除の行だけを省く: `"h30-h35"`と`"h36-h40"`のように、削除の前後で範囲を分ける
- `code`: `b`ならbase、`h`ならheadのファイルの行番号で指し、1つのブロックの中ではどちらかに揃える。スクリプトが`ref`を付ける。変更の無いファイルは`numbered-diff.mjs`に出ないので、そのcommitのファイルを行番号付きで読む
- `beforeAfter`: `before`はbaseのファイルの行番号を`b…`で、`after`はheadのファイルの行番号を`h…`で指す

展開すると、`range`と`lineNotes`は`lines`に置き換わる。`lines`は1行を1要素にした配列で、`diff`の行は先頭が`" "`・`"+"`・`"-"`か、`"@@"`で始まる。スクリプトは、`diff`の`" "`と`"+"`の行と`after`の行をhead、`"-"`の行と`before`の行をbase、`code`の行を`ref`のファイルと照らし、見つかった行に行番号と色分けを付ける。

base・head以外のcommitにしか無い行を見せる時は、`range`ではなく`lines`に行を写す。空白の変更も読み手が隠せるので、写す行は`-w`を付けないdiffから取る。

## 図

図はHTMLかインラインSVGで描き、1行を1要素にした配列で`figure`に入れる。属性を`'`で囲めば、JSONのエスケープが要らない。外部を読み込む記述（`src=`・`href=`・`@import`・`url(http…)`）を含むと、スクリプトがエラーで止める。

見た目を揃えるため、テンプレートが用意している次のクラスを使う。

| クラス | 使う物 |
|---|---|
| `fig-box` | 箱 |
| `fig-box-new` / `fig-box-old` | この変更で足した物 / 消した物の箱 |
| `fig-line` / `fig-line-return` | 矢印 / 戻りの破線の矢印。矢印の先は付いている |
| `fig-lifeline` | sequence diagramの縦の破線 |
| `fig-box-alt` | sequence diagramの分岐を囲む破線の枠と区切り線 |
| `fig-note` | 補足の吹き出し |
| `fig-title` / `fig-text` / `fig-label` | 太字の名前 / 本文 / 矢印のラベル |

- `<svg>`には`viewBox`と`width`を付ける。表示幅より広ければ縮んで収まる
- SVGの文字は折り返さないので、箱の幅は中の文字の長さに合わせる
- 流れは上から下へ一方向に置く。矢印の交差と、矢印が箱や文字の上を通る配置を避ける
- 箱の名前は実名（関数名・クラス名など）にし、責務を1行添える。矢印は、コードに実在する呼び出し・依存だけにする
- ラベルは2行以内にする
- 描画した後に、ブラウザやスクリーンショットで図の見た目を確かめない。崩れは読み手が見つけて伝える
