# HTMLで書く

資料のデータを`guide.json`に書き、描画スクリプトで1つのHTMLにする。HTMLは、外部（CDN、別ファイルのCSS・JS、ネットワーク）を何も読み込まずに表示できる1ファイルにする。diffの見た目（色分け、inline/splitの切り替え、空白の変更を隠す切り替え、変わった単語の塗り、注釈の見せ方）はスクリプトが揃えるので、`guide.json`には中身だけを書く。空白の変更も読み手が隠せるので、`diff`の行は`-w`を付けないdiffから写す。

## 作り方

1. `guide.json`を書く。HTMLと同じ場所に置く
2. 対象のリポジトリのルートで、このファイルからの相対パス`../scripts/render-html.mjs`をnodeで実行する。引数は`<guide.json> <出力するHTML>`。スクリプトは`base`・`head`のcommitからファイルを読むので、そのcommitがリポジトリにある必要がある
3. 形のエラーで止まったら、`guide.json`を直して作り直す。「実ファイルと合わない行」の警告は、写し間違いなら直す。途中のcommitにしか無い行を意図して見せている時は残してよい。その行は行番号が付かず、その行だけで色分けされる。直す時は該当する箇所だけを書き換え、`guide.json`全体を書き直さない

## guide.jsonの形

```json
{
  "title": "<何のための変更かを1行>",
  "base": "<PRの分岐元のcommit>",
  "head": "<PRのheadのcommit>",
  "map": { "figure": ["<単位どうしの関係の図>"] },
  "omittedFiles": ["<載せなかったファイルのパス>"],
  "checksSource": "<動作確認の出どころ。例: PR 本文の「動作確認」から。>",
  "checks": ["<動作確認したこと>"],
  "units": [
    {
      "title": "<単位名>",
      "nature": "<性質>",
      "why": "<なぜ>",
      "points": "<見るポイント>",
      "figure": ["<図>"],
      "blocks": ["<ブロック>"],
      "tests": {
        "groups": [{ "title": "<テストファイルなど>", "items": ["<確かめている仕様>"] }],
        "blocks": ["<テストのブロック>"]
      },
      "notes": ["<特記>", { "text": "<特記>", "items": ["<入れ子の項目>"] }]
    }
  ]
}
```

- `why`・`figure`・`tests`・`notes`・`omittedFiles`・`checksSource`・`tests.groups[].title`は、無ければ項目ごと省く
- 地図の表は、スクリプトが各単位の`title`と`nature`から作る。`omittedFiles`が空なら「なし」、`checks`が空なら「記載なし」と出す
- ファイルのパスは、リポジトリのルートから書く
- 文章の中で使える書式は`` `コード` ``だけ。箇条書きは配列にし、入れ子は`{ "text", "items" }`にする

### ブロック

| `kind` | 使う時 | 項目 |
|---|---|---|
| `diff` | diffで見せる時 | `file`、`caption`（省略可）、`lines` |
| `beforeAfter` | 構造や責務の移動 | `before`と`after`に、それぞれ1つ以上の`{ "file", "caption", "lines" }` |
| `code` | 変更の無いコードや、新規ファイルを全部追加の色にせずに見せる時 | `file`、`caption`（省略可）、`ref`（`"base"`か`"head"`。省略時は`"head"`）、`lines` |
| `text` | ブロックの間に挟む短い文 | `text` |
| `list` | 機械的な変更で、変更した箇所を一覧にする時など | `items`（箇条書きの配列） |

- `lines`は1行を1要素にし、実際のファイルから行をそのまま写す。`diff`の行は、先頭を`" "`・`"+"`・`"-"`にするか、`"@@"`で始める。`"@@"`の後ろに書いた文は、区切りの行にそのまま出る
- スクリプトは、`diff`の`" "`と`"+"`の行と`after`の行をhead、`"-"`の行と`before`の行をbase、`code`の行を`ref`のファイルと照らし、見つかった行に行番号と色分けを付ける
- 注釈（`[AI注]`を含むコメント）は照合から外れ、背景色で見分けられるように出る
- `beforeAfter`では、変更前と変更後の行を字下げを無視して比べ、片側にしか無い行を削除・追加の色で塗る。片側だけ省くと、もう片側の同じ部分が丸ごと塗られるので、省く部分は両側で揃える

## 図

図はHTMLかインラインSVGで描き、1行を1要素にした配列で`figure`に入れる。属性を`'`で囲めば、JSONのエスケープが要らない。外部を読み込む記述（`src=`・`href=`・`@import`・`url(http…)`）を含むと、スクリプトがエラーで止める。

見た目を揃えるため、テンプレートが用意している次のクラスを使う。

| クラス | 使う物 |
|---|---|
| `fig-box` | 箱 |
| `fig-box-new` / `fig-box-old` | この変更で足した物 / 消した物の箱 |
| `fig-line` / `fig-line-return` | 矢印 / 戻りの破線の矢印。矢印の先は付いている |
| `fig-lifeline` | sequence diagramの縦の破線 |
| `fig-box-alt` | sequence diagramの分岐を囲む破線の枠と区切り線 |
| `fig-note` | 補足の吹き出し |
| `fig-title` / `fig-text` / `fig-label` | 太字の名前 / 本文 / 矢印のラベル |

- `<svg>`には`viewBox`と`width`を付ける。表示幅より広ければ縮んで収まる
- SVGの文字は折り返さないので、箱の幅は中の文字の長さに合わせる
- 流れは上から下へ一方向に置く。矢印の交差と、矢印が箱や文字の上を通る配置を避ける
- 箱の名前は実名（関数名・クラス名など）にし、責務を1行添える。矢印は、コードに実在する呼び出し・依存だけにする
- ラベルは2行以内にする
