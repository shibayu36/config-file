# 図とデモの選び方

視覚表現は、読み手の問いから種類を決め、次に描き方を決める。種類（何を見せるか）と描き方（どう描くか）は別の軸として考える。

## 描くか

次のどれかに当たるときに描く。

- 4つ以上の要素とその関係がある
- 時間の順序がある
- 値や状態が段階的に変わる
- 包含関係や、前後の比較がある

答えが1文で済むとき、1つの関数の中身だけで済むときは描かず、サイドバーのコードと文章で説明する。

## 問いから図の種類を選ぶ

| 読み手の問い | 図の種類 |
|---|---|
| 誰が誰を、どの順で呼ぶか | シーケンス図 |
| 入口からどの関数をたどるか（順序より全体像） | コールツリー / コールグラフ |
| 条件によってどう分岐するか | フローチャート |
| 値がどう変換されて最後の形になるか | データフロー図（各段階に具体的な値を書く） |
| オブジェクトがどんな状態をとり、何で移るか | 状態遷移図 |
| どのモジュールがどれに依存しているか | 依存関係図 |
| どの層・境界をまたぐか（handler → service → repository、外部APIなど） | レイヤー図 / アーキテクチャ図 |
| クラスやテーブルがどう関係しているか | クラス図 / ER図 |
| 並行処理やイベントが、時間軸でどう重なるか | タイムライン / スイムレーン図 |
| ある時点で、データ構造の中身がどうなっているか | スナップショット図（配列・木・キャッシュなど） |
| 変更前後で何が変わったか | Before / After 比較 |

1つの問いに図は1枚。

## 設計表を作ってから描く

図やデモを作る前に、図に出す要素をコードから書き出した設計表を作り、図はこの表にあるものだけで描く。箱の並びから矢印を機械的に引かない。

| 表 | 列 |
|---|---|
| 箱 | 実名（クラス名・メソッド名・テーブル名）、責務1行、file:line |
| 矢印 | 元、先、渡すもの、file:line |
| 値 | 値、出どころ（テスト名・コード中のリテラルや定数・実行結果・例） |

- 箱の数を数え、10個程度を超えるなら、層や段階で図を分ける
- 箱の名前は実名にする。説明のために縮めるときは、本文かサイドバーで元の名前と対応づける
- 矢印は、コードに実在する呼び出し・依存・遷移だけにする。file:lineを書けない矢印は描かない
- 並列に動く処理は、一直線に並べず枝として描く。並列の処理同士で受け渡しが無ければ、矢印でつながない
- 値の出どころが「例」のもの（想像した値）は、図やデモの中でも見た目で区別し、「例」と分かるようにする
- 調査をサブエージェントに任せるときは、関数の行範囲だけでなく、関数同士の受け渡しとそのfile:lineも返させる

HTMLを生成した後、図と設計表を突き合わせ、表に無い箱・矢印・値が図に紛れていないか確かめる。

設計表はHTMLに載せず、最終報告に載せる。最終報告では、出どころが「例」の値も列挙する。

## デモにするか

次の問いでは、静的な図よりデモの方が伝わる。

| 読み手の問い | デモの形 |
|---|---|
| 値が各段階でどう変わるか | ステップ送り：データフロー図やシーケンス図を1段階ずつ進め、その時点の値を表示する |
| 入力が変わると、どの分岐を通って何が返るか | 入力プレイグラウンド：入力を変えると、通る分岐と出力が変わる |
| ループや再帰で、データ構造がどう育つか | ステップ送り＋スナップショット図：1手ずつデータ構造を描き直す |
| 並行処理の順序で結果がどう変わるか | タイムラインの再生：イベントの順序を入れ替えて結果を比べる |

依存関係・層の構造・ER図のように関係が静的に決まるものは、デモにしても情報が増えないので静的な図にする。

デモはコードの処理をJSで再現するので、推測で書いたコードを実コードのように見せないために次を守る。

- ステップ送りは、実際に実行した値やテストの入出力を埋め込んで再生する形を優先する
- 処理の再実装が要るデモ（入力プレイグラウンドなど）は、「簡略化した再現」であることと、再現していない条件をデモの近くに書き、元の処理のfile:lineへリンクする

## 描き方

図とデモは、外部リソースを読み込まずに表示できるよう、HTML・インラインSVG・CSS・JSでHTMLに組み込む。

箱と矢印の関係で伝わる図（シーケンス図、コールツリー、フローチャート、状態遷移図、依存関係図、レイヤー図、クラス図、ER図）は、配置を単純に保つ。

- 流れは上から下へ、一方向に置く。横に長い流れは狭い画面で文字が潰れる
- 矢印の交差と、矢印が箱や文字の上を通る配置を避ける。避けられないなら箱の並びを変えるか、図を分ける
- ラベルは2行以内にし、矢印のラベルには何を渡すかを書く

位置や値そのものを見せる図（具体的な値を載せたデータフロー図、スナップショット図、タイムライン、Before / After）は、表に近い形で値を揃えて並べ、段階ごとの差分を色や枠で示す。
