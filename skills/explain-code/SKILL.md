# explain-code

「知りたいこと」を、このコードを初めて見る開発者向けに、1つの自己完結したHTMLで解説する。

- 「知りたいこと」に答える構成にする。それが広すぎて答える範囲が定まらないときだけ、生成前に1〜2問聞いて絞る。問いを推測して勝手に増やさない
- 図・アニメーション・操作できるデモなどの視覚表現を大きく見せ、少ない言葉で、上から順に読める一本道の物語にする
- 具体例を1つ軸に、その値や状態が各段階でどう変わるかを、視覚表現の中で追えるようにする。性質の違う例が必要なら短く足す
- 視覚表現は、知りたいことが最も伝わるものを選ぶ。すべての種類を盛り込む必要はない
- 文章や表、入出力例などで理解を補い、ルールや分岐には「なぜそうなっているか」を一言添える
- メソッドの関係を図で示す場合は、1つの図に整理する。各メソッドは責務を1行で、矢印には「何を渡すか」を書く
- 解説内で file:line を指す箇所は、クリックすると本文と並べて読めるサイドバーにメソッド本体が開くようにする。本体は実ファイルから省略せず写し、分かりにくい箇所には対象言語のコードコメントとして短い注釈を加える。元の処理や既存コメントは変えず、推測で書いたコードを実コードのように見せない

## サイドバーの表示

HTMLを生成する前に、このSKILL.mdからの相対パス `references/sidebar.md` を読み、配置・コード表示の実装例を参考にする。解説全体の構成は固定しない。

- 初期状態ではサイドバーを閉じ、本文が余白を除く表示領域全体を使う。開いたときだけ本文とサイドバーを半分ずつにし、閉じたら本文幅を戻す
- コード領域はVS CodeのDark+に合わせて構文を色分けし、等幅フォントで、文字が小さすぎずインデントや行間を見分けやすい表示にする。実装例の初期値は15px・行高1.6
- 元の改行・インデントを保ち、空白のない長い文字列も折り返す。横スクロールや文字の切り捨てで収めず、全文を読めるようにする
- 注釈は別列や吹き出しに分けず、通常のコードコメントと同じ見た目で表示する。行末に追加できる場合は行末に置き、構文や処理に影響する場合は直前の独立したコメント行にする
- 色分けに必要なHTMLとCSSは生成時に組み込み、閲覧時の外部読み込みに依存しない。注釈を加えたコードをHTML用にエスケープし、色分けできない場合も全文を表示する

生成したファイルのパスを報告する。「ここをもっと詳しく」と頼まれたら新規作成せず同じファイルに追記する。
