# sidemark-watch

Sidemarkは、ノートへのコメントを隣のsidecarファイル `<ノート>.review.yaml` に保存する。Obsidianは、外から書き換えられたsidecarをすぐ画面に反映する。この性質を使い、本人のコメントを `watch.rb` で拾い、sidecarに直接返信を書く。

## 監視を始める

1. 監視するノートを決める。引数で指定されたらそれを使う。無ければ、このセッションで読んだり編集したりしたObsidianのノートを使う。どちらも無ければ本人に訊く
2. 監視するノートの一覧を本人に示す
3. 状態ファイルのパスを、このセッション用に1つ決める。vaultの外に置く。張り直す時も同じパスを使う
4. 出力の1行ごとに起こされる監視（Claude CodeならMonitor）として、次のコマンドを期限を最大にして動かす

    ```sh
    /usr/bin/ruby <このskillのディレクトリ>/watch.rb --state <状態ファイル> <ノートの絶対パス>...
    ```

    - 他のrubyではなく `/usr/bin/ruby` を使う。`ruby` コマンドは、ディレクトリによって別の版に切り替わることがある
    - 状態ファイルが無いsidecarは、その時点のコメントを読み済みとして記録するだけで、何も出力しない

## 監視を張り直す

次の時に、動いている監視を止め、同じ状態ファイルで張り直す。止まっていた間に増えたコメントは、張り直した時に出力される。

- 監視が期限で切れた時
- このセッションで新しいノートを扱い始めた時。そのノートを監視対象に加える

本人に止めるよう言われたら、監視を止める。

## 出力への対応

### `{"event":"comment", ...}`

本人が `@ai` を付けたコメントである。`note` がノートの絶対パス、`id` がコメントのid、`reply_to` が返信先のidである。

1. sidecarとノートを読む。スレッド全体（`reply_to` をたどって根に着くコメントすべて）と、根のコメントが指すノートの箇所を把握する。`@ai` を付けたコメントだけでなく、スレッド全体が依頼の文脈である
2. スレッドに返信する。文章の変更を求められたら、修正提案（suggestion）を新しいスレッドとして書き、元のスレッドにもその旨を返信する
3. ノート本体は編集しない。resolve・accept・declineやコメントの削除もしない。本人がObsidianで行う
4. チャットでは、対応したコメント1件につき1行で、どのコメントに何をしたか（返信した・修正提案を書いた）だけを報告する。書いた内容は本人がObsidianで読むので繰り返さない。出力されなかったコメントには触れない

### `{"event":"error", ...}`

`note` のsidecarを読めない状態が続いている。本人に知らせる。読めるようになるまで、そのsidecarに書き込まない。

## sidecarへの書き込み

- 書く直前にsidecarを読み直す。Sidemarkは、本人がノートを編集するたびにsidecarを書き直す
- 新しいコメントは `comments` の末尾に足す。他の部分は1バイトも変えない
- 書いた後、YAMLとして解析できることを確かめる
- `author` は `Claude` にする。`shibayu36` で書くと、`watch.rb` が本人のコメントとして扱う
- `id` はランダムなUUID（小文字）にする
- `timestamp` は、書く直前に時計から読んだUTCのISO 8601（例: `2026-11-14T05:45:19Z`）にする。Sidemarkはスレッド内をこの順に並べる
- `text` はMarkdownとして表示される。YAMLとして誤読されうる文字列（`@` で始まる、`: ` を含む等）はダブルクォートで囲む

### 返信

`id`・`author`・`timestamp`・`text`・`resolved: false`・`reply_to: <返信先のid>` を書く。位置の項目は書かない。

### 修正提案（suggestion）

次の項目を持つ、新しい根のコメントを書く。

| 項目 | 内容 |
| --- | --- |
| `text` | 提案の理由。無ければ `""` |
| `resolved` | `false` |
| `type` | `suggestion` |
| `line` / `end_line` | 対象箇所の行。1始まりで、frontmatterも数える |
| `start_column` / `end_column` | 行内の位置。0始まりで、`end_column` はその文字を含まない。UTF-16の単位で数える |
| `selected_text` | 対象箇所の文字列そのもの |
| `selected_text_hash` | `selected_text` のSHA-256（小文字の16進） |
| `x_prefix` / `x_suffix` | 対象箇所の直前・直後の最大20文字。改行をまたいでよい |
| `x_suggestion` | `{ replacement: <置き換え後の文字列> }`。削除の提案は `replacement: ""` |

書いた後、ノートの `line` 行目の `start_column` から `end_column` までが `selected_text` と一致することを確かめる。
